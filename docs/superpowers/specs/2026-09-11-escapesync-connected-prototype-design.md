# EscapeSync Connected Prototype Design

## الهدف

تحويل صفحات EscapeSync التسع الحالية إلى نموذج تفاعلي واحد مترابط ببيانات محاكاة، مع الحفاظ على الهوية البصرية والتفاعلات الموجودة وجعل كل زر ظاهر يؤدي وظيفة مفهومة.

## حدود العمل

المشروع نموذج Frontend محلي فقط. لا يشمل backend أو حسابات حقيقية أو قواعد بيانات أو إرسال رسائل حقيقي أو خدمات طقس وحجوزات. الخرائط الحالية تظل معتمدة على Leaflet وOpenStreetMap، بينما بقية الخدمات الخارجية تُحاكى داخل الواجهة.

## البنية

تبقى ملفات HTML الحالية منفصلة. يضاف ملف `app.js` مشترك يحمّل في كل مرحلة ويقدّم واجهة واحدة لإدارة:

- خريطة المسارات بين الصفحات.
- قراءة حالة الرحلة وتطبيعها وحفظها في `localStorage`.
- الانتقال إلى صفحة مع hash أو query state مناسب.
- إشعارات النجاح والخطأ والنوافذ التجريبية المشتركة.
- محاكاة تسجيل الدخول والمشاركة والصوت والإرسال.

تظل controllers الموجودة داخل ملفات `text/x-dc` مسؤولة عن حالة الشاشة المحلية. تستدعي هذه controllers الواجهة المشتركة عند الانتقال أو حفظ بيانات رحلة بدلاً من تكرار منطق التنقل والتخزين.

## حالة الرحلة المشتركة

تُحفظ الحالة تحت مفتاح إصدار ثابت، وتحتوي على:

- نقطة البداية والوجهة.
- تاريخ البداية والنهاية.
- عدد المسافرين وأسماؤهم.
- الميزانية الإجمالية والميزانية لكل شخص.
- نمط السفر والتفضيلات المختارة.
- مستوى توافق المجموعة.
- حالة الرحلة الصحية.
- العطل المختار وخطة الإنقاذ المقبولة.
- المصروفات والتوصيات المضافة.
- آخر شاشة مكتملة.

أي قيمة مفقودة أو غير صالحة تستبدل بالقيمة الافتراضية المناسبة. إذا تعذر فك JSON، تُستعاد الحالة الافتراضية من دون تعطيل الصفحة.

## مسار المستخدم الرئيسي

1. Phase 1 تعرض المنتج والهوية، وتبدأ الرحلة عبر زر Start Your Escape.
2. Phase 2 تمر بخمس خطوات: الوجهة، التواريخ، الفريق، الميزانية، ونمط السفر.
3. تبويب Crew يجمع تفضيلات أعضاء المجموعة.
4. تبويب Balance يعرض التوافق ويقود إلى Phase 3.
5. Phase 3 هي مركز التنقل إلى الخريطة والإنقاذ والميزانية والتوصيات وPip والجوال.
6. Phase 5 تنفذ مسار العطل، المعالجة، مقارنة Plan B، والقبول.
7. قبول Plan B يعيد إلى Phase 3 بحالة رحلة محدثة.
8. Phase 9 تشغّل المسار التجريبي وتفتح كل خطوة في الحالة المقصودة.

`EscapeSync Home.html` ليس صفحة مستقلة في التدفق. يحوّل إلى Phase 1، وهي الصفحة الرئيسية الرسمية.

## وظيفة الصفحات والأزرار

### Phase 1 — Landing and Brand

- Product ينتقل إلى قسم المزايا.
- Rescue Mode ينتقل إلى بطاقة Rescue Mode ثم يتيح فتح Phase 5.
- Pricing وAbout يفتحان نافذتين تجريبيتين واضحتين.
- Sign In يفتح نموذج دخول تجريبي ولا ينشئ حساباً حقيقياً.
- Get Started وStart Your Escape يفتحان Phase 2.
- Watch How It Works يفتح شرحاً مختصراً للتدفق مع زر Run Demo إلى Phase 9.
- See Plan B يفتح Phase 5 في حالة Plan B.

### Phase 2 — Trip Builder, Crew, and Balance

- Create Trip وCrew وBalance يبدّلون العرض المقصود ويحفظون آخر شاشة.
- Continue وBack يتنقلان بين الخطوات الخمس مع منع النزول دون الخطوة الأولى.
- حقول الوجهة والتاريخ والميزانية وعدد المسافرين والتفضيلات تحفظ في الحالة المشتركة.
- Continue بعد الخطوة الخامسة يفتح Crew، ثم Balance، ثم Phase 3.
- أزرار الاختيار والتبديل والمنزلقات تعدّل الحالة المرئية والمشتركة.

### Phase 3 — Command Center

- عناصر الشريط الجانبي تفتح الشاشة الداخلية أو المرحلة المطابقة.
- Map Explorer يفتح Phase 4.
- Rescue Mode يفتح Phase 5.
- Budget Brain وRecommendations يفتحان Phase 6 بالتبويب المناسب.
- Crew يعيد إلى Phase 2 على Crew.
- Pip Assistant يفتح Phase 7.
- Trip History وSettings يفتحان نافذتين محاكيتين.
- Trip Health يفتح تفاصيل الصحة داخل الصفحة.
- البيانات المعروضة تُشتق من حالة الرحلة المشتركة عند الإمكان.

### Phase 4 — Map Explorer

- Web وMobile يبدّلان تخطيط العرض.
- Map وSatellite و3D تغير مظهر الخريطة وحالتها.
- Walk وCar وTransit تغيّر ملخص الطريق.
- أدوات الخريطة ونقاط التوقف والبطاقات تعمل وتعرض التوقف المحدد.
- Compare state يعرض مسار الخطة الأصلية وخطة الإنقاذ.
- Back يعيد إلى Phase 3 أو Phase 5 عند الدخول من المقارنة.

### Phase 5 — Rescue Mode

- Trigger وProcessing وWhat Changed تفتح حالات المرحلة مباشرة.
- اختيار العطل يحدّث الحالة.
- Break My Plan يبدأ معالجة محاكاة زمنية ثم يعرض Plan B.
- See What Changed يعرض المقارنة.
- Compare on Map يفتح Phase 4 في وضع المقارنة.
- Try Another Plan يولد بديلاً محاكياً جديداً.
- Accept Plan B يحفظ خطة الإنقاذ ويعيد إلى Phase 3 بحالة Updated.
- Reset يعيد سيناريو الإنقاذ إلى بدايته.

### Phase 6 — Budget and Recommendations

- التبويبات تبدّل Budget Brain وExpense Splitter وSmart Options.
- تعديلات المصروفات تعيد حساب المتبقي ضمن البيانات المحاكاة.
- التحويلات بين الأعضاء تغير حالة التسوية.
- خيارات التوصيات تعرض السبب وتسمح بإضافة العنصر للرحلة.
- Back يعيد إلى Phase 3.

### Phase 7 — Pip Assistant

- Chat وVoice يبدّلان العرض.
- Send والاقتراحات السريعة تنتج رداً محاكياً مناسباً للنص أو الاختيار.
- Preview Change يفتح ملخص التغيير.
- Apply Change يحفظ التغيير ويعرض نجاحه.
- وضع Voice يعرض Listening ثم Processing ثم استجابة مرئية، دون استخدام الميكروفون فعلياً.
- Back يعيد إلى Phase 3.

### Phase 8 — Mobile Screens

- الشاشات الثماني تصبح قابلة للاختيار والمعاينة.
- عناصر bottom navigation داخل العرض تغيّر الشاشة النشطة.
- أزرار الخطر والإنقاذ والخريطة تفتح الحالات المطابقة داخل المعاينة أو المرحلة المناسبة.
- Back يعيد إلى Phase 3.

### Phase 9 — Demo and Share

- Run Demo يبدأ من Phase 1.
- الخطوات التسع عشرة تفتح المرحلة مع hash state الصحيح.
- Share Trip يفتح نافذة المشاركة.
- Copy Link ينسخ رابطاً تجريبياً أو يعرضه للمستخدم عند منع Clipboard.
- WhatsApp وEmail يعرضان معاينة رسالة جاهزة من دون إرسال.
- QR Code يبدّل عرض رمز الانضمام التجريبي.
- كل Secondary Flow يفتح بدايته الصحيحة.
- Back يعيد إلى Phase 3.

## إصلاحات مطلوبة ضمن الربط

- إضافة أو استبدال صورة Hero المفقودة بحيث لا يبقى طلب 404.
- منع تمرير `{{ mapRoute }}` الخام إلى SVG قبل حل القيمة.
- منع تمرير `{{ it.photo }}` و`{{ sel.photo }}` و`{{ nextPhoto }}` الخام إلى `image-slot`.
- جعل `.image-slots.state.json` اختيارياً بصمت، لأنه غير مطلوب لتشغيل النموذج.
- توفير placeholder واضح للصور الخارجية الفاشلة.
- توفير fallback للخريطة عند تعذر Leaflet أو OpenStreetMap.

## واجهة المحاكاة المشتركة

النوافذ المحاكية تحمل عنواناً واضحاً مثل “Demo sign-in” أو “Share preview”، وتذكر أن الإجراء محاكى. يمكن إغلاقها بزر واضح، بالنقر خارجها، أو بزر Escape. إشعارات الأفعال القصيرة تستخدم toast يمكن قراءته من قارئات الشاشة.

## الوصول وتجربة الاستخدام

- كل زر رمزي يحصل على `aria-label` مناسب.
- كل نافذة تحصل على دور dialog وعنوان يمكن الوصول إليه.
- التركيز ينتقل إلى النافذة عند فتحها ويعود إلى الزر عند إغلاقها.
- أزرار غير متاحة مؤقتاً تستخدم disabled بدلاً من تجاهل النقر.
- التنقل بلوحة المفاتيح وEscape مدعومان في النوافذ والتفاعلات الأساسية.
- يبقى التصميم متجاوباً عند عرض 375×812 و1440×900.

## الاختبارات

تُستخدم اختبارات Node المضمنة بلا إضافة إطار عمل ثقيل:

- اختبار خريطة المسارات لكل مرحلة وحالة.
- اختبار الحالة الافتراضية، الدمج، القيم التالفة، والحفظ.
- اختبار أن كل رابط داخلي يشير إلى ملف موجود.
- اختبار inventory للأزرار الحرجة وأن لها action محدداً.
- اختبار عدم وجود مصادر ديناميكية خام من شكل `{{ ... }}` في السمات التي يطلبها المتصفح.

ثم يُجرى اختبار متصفح للمسار الكامل:

- Phase 1 إلى Phase 3 عبر خطوات الإنشاء.
- جميع فروع Command Center والرجوع منها.
- Rescue Mode حتى قبول Plan B.
- Demo flow وروابط المشاركة.
- فتح المراحل التسع على سطح المكتب والجوال.
- عدم وجود أخطاء JavaScript أو طلبات 404 لازمة للتشغيل.

## معايير القبول

- كل زر ظاهر له نتيجة واضحة وقابلة للملاحظة.
- المسار الرئيسي يعمل من البداية حتى لوحة القيادة المحدثة.
- البيانات الأساسية تبقى متسقة بعد التنقل وإعادة التحميل.
- لا توجد روابط داخلية مكسورة أو assets محلية مفقودة.
- لا تصل قوالب `{{ ... }}` الخام إلى SVG أو طلبات الصور.
- الصفحات التسع تعمل على قياسي الجوال وسطح المكتب المحددين.
- الاختبارات التلقائية واختبار المتصفح يمران بلا أخطاء تشغيل مؤثرة.
